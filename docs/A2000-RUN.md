# Running the benchmark on the RTX A2000 (feature 002, US1)

Feature 001 measured CorridorKey on the RTX 3060 only. Its RTX A2000 figures are **estimates**
(x1.25–1.59 of the 3060), and an estimate must be confirmed on the card before the plugin is
relied on. This page is the exact procedure for the production machine. The result becomes the
A2000 row of the plugin's Auto table (`plugin/data/perf-table.json`).

Prerequisites are in [issue #2](https://github.com/KennyLowe/CorridorKey-OBS/issues/2): the driver,
Git, uv, ffmpeg 7.1.1 and TensorRT, all from **direct downloads with hash checks (no winget or
choco)**. Do that first. Run everything below in PowerShell.

## 1. Check and record the driver

```powershell
nvidia-smi --query-gpu=name,driver_version --format=csv
```

- It must show **NVIDIA RTX A2000** (or `RTX A2000 12GB`) and a driver **≥ 576**. Write the
  version down; the run records it too. Known good on the production machine: **597.16**
  (RTX A2000 12GB, 12282 MiB; torch 2.8.0+cu128, TensorRT 10.16.1.11, ffmpeg 7.1.1 with h264_nvenc).
- **If the driver is lower than 576: stop here and tell Kenny.** The pinned PyTorch (cu128) needs
  it. The choice is between updating the driver and pinning older wheels, and that's an owner
  decision.

## 2. Get the code at the release tag

```powershell
git clone https://github.com/KennyLowe/CorridorKey-OBS C:\git\corridorkey   # skip if already cloned
cd C:\git\corridorkey
git fetch --tags
git checkout v0.1.0-rc.3
```

The tag matters: the default branch doesn't have the model manifest or the plugin's helper
commands until the feature-002 pull request is merged.

## 3. Set up the benchmark environment

```powershell
cd C:\git\corridorkey\bench
.\setup.ps1
```

`setup.ps1` clones CorridorKey at the pinned commit, downloads the official weights
(`models/manifest.json`: Hugging Face `nikopueringer/CorridorKey_v1.0`, sha256 `74d614f7…b20b`,
checked), runs `uv sync` and checks CUDA and NVENC. It should end by printing
`torch … NVIDIA RTX A2000` and a working `h264_nvenc`.

Optional but recommended: copy the Hollywood Camera Work plates ("Locked Backdrop", "Godiva
Close") into `C:\git\corridorkey\footage\hcw\<name>\` as PNG sequences (see `bench/README.md`).
Without them, the quality step uses only the three public clips.

## 4. Run the benchmark

**Corporate network (the production machine): speed only.** That network blocks the public clips
(Pexels 503, Pixabay CDN 404), so run without the clips and the quality step:

```powershell
cd C:\git\corridorkeyench
uv run ckbench all --speed-only
uv run ckbench --run-id <run-id> report --allow-pending --quality-from 20261016T221252Z-c16425
```

`--speed-only` runs env, export (including the 16:9 sizes), idle speed and the NVENC-load speed
runs, then a report. The report says "quality not run on this machine". With `--quality-from` it
instead borrows the RTX 3060 run's owner verdicts by configuration: same model, same outputs on any
GPU, so only speed differs. `perf-table` doesn't need quality either; a configuration fits on
timing unless a verdict failed.

**Full run (where the clips can be downloaded), about 6 hours:**

Close OBS and anything else that uses the GPU, and stop the machine from sleeping. Then:

```powershell
cd C:\git\corridorkey\bench
uv run ckbench all
```

It writes `bench/results/<run-id>/results.json` and a draft `REPORT.md`. The run id is printed at
the start (`run_id 2026…`).

- Exit code 0 means it's complete; 2 means partial (some configuration ran out of memory or
  failed to export; that is recorded and is a valid result).
- Quality review: the draft report lists pending owner verdicts. Review the comparison material in
  `outputs\compare\index.html` and record each verdict with
  `uv run ckbench --run-id <run-id> review --config <id> --clip <id> --verdict pass|fail`.
  Then `uv run ckbench --run-id <run-id> report` writes the final report. If you prefer not to
  review on that machine, skip this: the draft is enough for the speed envelope, because the
  owner already accepted quality at every setting on the 3060 (`perf-table` uses speed plus
  "not failed").

## 5. Regenerate the Auto table

```powershell
cd C:\git\corridorkey\bench
uv run ckbench perf-table
```

`plugin/data/perf-table.json` now has an `NVIDIA RTX A2000…` entry next to the RTX 3060 one.

## 6. Commit the results on a branch

```powershell
cd C:\git\corridorkey
git switch -c a2000-run
git add bench/results plugin/data/perf-table.json
git status            # only bench/results/<run-id>/ and perf-table.json; no outputs/, footage/ or weights
git commit -m "bench: RTX A2000 run <run-id>"
git push -u origin a2000-run
```

Push the branch, or zip `bench\results\<run-id>\` and send it.

## 7. Afterwards (any session)

- Add the measured vs estimated comparison below (done for run `20261019T122416Z-e45fdf`).
- Rebuild the plugin release with the new `perf-table.json` (done: v0.1.0-rc.2). With an older build,
  Auto on the A2000 treats it as an unknown GPU and uses the fastest setting (512×512) with a
  warning (FR-015).

## Measured vs estimate

Measured on 2026-10-19, run `20261019T122416Z-e45fdf`: NVIDIA RTX A2000 12GB, driver 597.16, speed-only
on the corporate network. The run was interrupted by a forced reboot and resumed in place, with the
NVENC-load runs added to the same results. Figures are p95 end-to-end under a concurrent 1080p30 NVENC
encode. The table compares them with feature 001's estimate:

| mode | budget ms | ESTIMATE status | ESTIMATE best config | ESTIMATE range ms | A2000 measured |
|---|---|---|---|---|---|
| 720p20 | 50.0 | supported | 768×768 r0 | 34.6–44.0 | **supported**, 1024×576 r0 at 43.0 |
| 720p30 | 33.3 | supported | 768×448 r0 | 21.7–27.6 | **supported**, 768×448 r0 at 23.9 |
| 1080p30 | 33.3 | supported | 768×448 r0 | 24.3–30.9 | **supported**, 768×448 r0 at 26.1 |
| 1080p60 | 16.7 | unsupported | 512×512 r0 | 19.6–25.0 | **unsupported**: fastest is 512×512 r0 at 20.8 |
| 2160p30 | 33.3 | unsupported | 512×512 r0 | 40.1–51.0 | **unsupported**: fastest is 512×512 r0 at 35.3 |

- Every mode landed as estimated. The 1080p30 figure (26.1 ms) is inside the estimated range,
  towards its optimistic end. Under load the A2000 is about 1.34× the RTX 3060 (768×448 r0 at
  1080p: 19.5 → 26.1 ms).
- The refiner doesn't fit 1080p30 on the A2000 at any size (768×448 r1: 45.0 ms; 512×512 r1: 35.8 ms).
- `plugin/data/perf-table.json` now has an `NVIDIA RTX A2000 12GB` entry. Auto picks 768×448 r0 for
  1080p30 on that card.

## Troubleshooting: corporate networks

- **`ckbench` says git refused the CorridorKey checkout ("dubious ownership"):** the folder belongs
  to another account (for example, it was cloned from an elevated prompt). `setup.ps1` and
  `ckbench` print the exact fix, for example
  `git config --global --add safe.directory C:/git/corridorkey/bench/vendor/CorridorKey`. Run it
  yourself; nothing changes your global git config automatically.
- **A public clip won't download (HTTP 503/404):** `ckbench clips` prints the manual route. Open the
  clip's page in a browser and save it under `footage\public\`, or copy it from another machine.
  `clips.toml` pins each file's sha256 and warns (doesn't fail) on a mismatch. Or skip clips
  entirely with `--speed-only` (section 4).
- **`CRYPT_E_NO_REVOCATION_CHECK` / `CRYPT_E_REVOCATION_OFFLINE`** (curl exit 35, or git
  "schannel: next InitializeSecurityContext failed"): the network blocks the certificate revocation
  server. `setup.ps1` retries once by itself with revocation checking off for that one command
  (`curl --ssl-no-revoke`, `git -c http.schannelCheckRevoke=false`) and prints a warning. The weights
  are still verified against the pinned sha256, and CorridorKey against its pinned commit. By hand:
  `curl.exe -L --ssl-no-revoke -o <file> <url>`. Global git config is never changed.
- **`invalid peer certificate: UnknownIssuer`** from `uv` (HTTPS inspection with a corporate root
  certificate): `setup.ps1` retries `uv sync` once with `UV_SYSTEM_CERTS=1` (current uv, e.g. 0.13.1)
  and `UV_NATIVE_TLS=1` (older uv), so uv uses the Windows certificate store. For other `uv` commands,
  set them yourself first: `$env:UV_SYSTEM_CERTS = "1"; $env:UV_NATIVE_TLS = "1"`.
- **The weights download can't get through at all:** download
  `CorridorKey_v1.0.safetensors` on another machine from
  <https://huggingface.co/nikopueringer/CorridorKey_v1.0> (revision `f6386ddf…`). Copy it to
  `bench\vendor\CorridorKey\CorridorKeyModule\checkpoints\` and re-run `setup.ps1`, which then only
  verifies the sha256 (`74d614f7…b20b`). The OBS plugin accepts the same file through "Use a local
  file…".
